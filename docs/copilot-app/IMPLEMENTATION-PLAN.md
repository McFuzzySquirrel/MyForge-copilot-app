# MyForge Copilot app: canvas-led implementation plan

**Status:** Approved direction; implementation has not started. The previous
engine-port plan and its phase documents are superseded. Their
[feasibility evidence](evidence/README.md) remains historical, not a current
acceptance gate.

## Product direction

MyForge will guide an idea through optional research, a reviewed specification,
a reviewed multiphase implementation plan, team and skill preparation, and an
orchestrated build. A canvas-type interface drives the journey. The specification
contains user stories, functional requirements and acceptance criteria. The
implementation plan contains bounded work items, dependencies, phase gates and
evidence; it is the execution source of truth, not a separate task backlog or
generated execution manifest.

An orchestrator manages specialists, verifies their work and updates the plan.
Prefer separate app-managed sessions when supported; show and use orchestrator
subagents as the approved fallback when separate sessions are unavailable. Do not
silently substitute a CLI, detached engine or undocumented API.

Reuse appropriate existing agents, skills and code, but do not depend on the
standalone Forge launcher, engine or execution adapter. Remove those components
after their dependencies have been inventoried and replaced. Research is
optional and user-directed. Recommend discovered skills with provenance and
trust information; never install them without user approval.

Review the specification and plan before execution. During execution, pause for
blockers or consequential decisions, not automatically at every phase boundary.
An agent cannot grant human approval.

## Phase graph and evidence

```text
N00 -> N01 -> N02 -> N03 -> N04 -> N05 -> N06
```

Each phase has stable work IDs, explicit outcomes and a gate. Work and gate
status must link to real evidence using the
[evidence protocol](evidence/README.md); do not mark a check passed if it was
not executed. A phase gate is distinct from completing a work item. The plan
below tracks this product's implementation; projects generated by MyForge
maintain their own plans and evidence.

| Phase | Purpose | Gate |
| --- | --- | --- |
| N00 | Replace port-planning baseline | New direction and preserved evidence are navigable |
| N01 | App capability and product contracts | Copilot app supports a safe execution path or implementation is blocked |
| N02 | Idea, research and specification | Reviewed spec from either research path |
| N03 | Plan and team preparation | Reviewed plan, validated team and approved skills |
| N04 | Orchestrator execution | Real bounded execution, verification, failure and recovery |
| N05 | Canvas integration | Accessible end-to-end app journey |
| N06 | Retirement and qualification | No standalone runtime dependency; release evidence accepted |

## N00: replacement baseline

- **N00-W01:** Replace the active engine-port plan and phase documents; preserve
  their evidence, including failures, as historical findings.
- **N00-W02:** Update active navigation, documentation map, changelog and
  architectural decision; distinguish planned behavior from the inherited
  standalone implementation.
- **N00-W03:** Inventory inbound references and validate changed links; do not
  rewrite historical ADRs or changelog records.

**Gate:** One active implementation plan reflects the pivot; old phase gates are
not presented as active; historical findings remain accessible.

## N01: app capability and contracts

- **N01-W01:** Verify canvas loading, actions, workspace access and distinct
  app-managed session dispatch on a named app/version. Independently test the
  subagent fallback, identities, visibility, interruption and workspace limits.
  Reuse prior evidence only within its actual scope. An opt-in
  [subagent probe](probes/workflow-subagent/README.md) was run and established
  only that one bounded worker can return its exact marker. Session-scoped
  canvas probes confirmed discovery, open/action routing, read access and
  limited extension-origin writes on Copilot desktop 1.5.0
  ([E-N01-012](evidence/README.md#e-n01-012-extension-origin-workspace-write-probes)).
  An app conversation created a separate worktree session and received
  its marker handoff. A separate extension-origin dispatch attempt returned
  that session management was disabled
  ([E-N01-011](evidence/README.md#e-n01-011-extension-origin-session-dispatch)).
  Specialist identity/isolation and interruption/recovery remain unverified.
  The [fallback qualification research](../research/copilot-app-workflow-fallback-qualification.md)
  distinguishes documented workflow APIs from historical host observations.
  A bounded workflow-owned worker cancellation was observed
  ([E-N01-015](evidence/README.md#e-n01-015-workflow-owned-worker-cancellation));
  a separate interruption attempt recovered run observation but could not
  establish whether app quit caused the worker to stop
  ([E-N01-017](evidence/README.md#e-n01-017-active-worker-interruption-attempt)).
  Neither qualifies interrupted-task recovery.
- **N01-W02:** Define versioned authoritative project artifacts for idea,
  research, specification, implementation plan, review, team and evidence.
  The [v1 contract basis](contracts/v1/README.md) selects `.myforge/` after a
  read-access probe and has operator acceptance. A disposable extension wrote
  a repository fixture, but an operator-assisted attempt did not establish an
  unsaved editor draft
  ([E-N01-013](evidence/README.md#e-n01-013-operator-assisted-editor-draft-attempt)).
  A workspace-view attempt also saved the fixture
  ([E-N01-018](evidence/README.md#e-n01-018-workspace-draft-investigation)).
  A local stale-write experiment rejected an already-stale draft but exposed a
  check-to-rename race with an external writer
  ([E-N01-019](evidence/README.md#e-n01-019-stale-write-filesystem-experiment)).
  The inspected session-workspace write API is unconditional; the host's
  conditional draft-resolution tools require a pending request and have not
  been qualified as an extension project-artifact write API
  ([E-N01-020](evidence/README.md#e-n01-020-conditional-write-boundary-inspection)).
  Until a suitable boundary is demonstrated, automated replacement must remain
  blocked rather than rely on check-then-rename.
  Host-managed reconciliation and recovery still require verification. The
  contract defines stable IDs, dependencies, edit reconciliation and review
  invalidation.
- **N01-W03:** Specify explicit mode selection and handoffs, failure handling,
  partial-work reconciliation and safe operator-led recovery. If no supported
  execution path exists, block visibly. Do not assume exactly-once dispatch,
  parallel isolation or continuation after app closure. The proposed
  [execution contract](contracts/v1/execution.md) requires operator review.
- **N01-W04:** Record the tested Copilot app and API versions; resolve
  distribution, permissions and storage decisions before dependent work. Rely
  on the app's supported platforms rather than creating a separate OS support
  matrix; document a platform-specific limitation if actually encountered.
  Distribution was deferred by the operator and remains unresolved.

**Gate:** A reviewed contract and real-host evidence establish an execution
path. Missing capabilities remain blocked, never passed by mock.

## N02: idea, research and specification

- **N02-W01:** Adapt idea-interview and specification authoring skills for
  interactive capture and optional user-directed research with linked sources,
  findings and uncertainty.
- **N02-W02:** Produce a concise spec with user stories, functional requirements
  and acceptance criteria; require operator review and support edits.
- **N02-W03:** Preserve existing project artifacts and handle changed approved
  content by invalidating relevant review and reconciling downstream plans.

**Gate:** A real canvas journey produces a reviewed spec both with and without
research; errors and revisions are visible.

## N03: plan and team preparation

- **N03-W01:** Create a plan-authoring skill producing phases and bounded work
  items with stable IDs, ownership, prerequisites, deliverables, verification,
  acceptance, status and evidence links. Trace work to the approved spec.
- **N03-W02:** Adapt team and skill generation to this plan. Reuse suitable
  existing assets, generate project-specific assets when needed and validate
  ownership, format and associations.
- **N03-W03:** Provide optional skill discovery with provenance, compatibility
  and trust details. Require explicit approval before installation or
  replacement; avoid overwriting user content.
- **N03-W04:** Require human approval of the plan before execution and again
  after substantive changes; do not generate a separate task manifest.

**Gate:** The reviewed plan is traceable, bounded and executable by the
prepared team; discovered skills are installed only with approval.

## N04: orchestrator execution

- **N04-W01:** Adapt the orchestrator agent and skill to select ready work,
  dispatch bounded briefs through the tested host mode and receive handoffs.
- **N04-W02:** Independently verify outputs and declared checks, update the
  authoritative plan and record actual mode, attempt, identity where available,
  changes, outcomes and blockers. Missing outputs, failed checks and
  interruptions are not success.
- **N04-W03:** Respect dependencies and phase gates. Parallelize only when
  supported isolation is demonstrated; otherwise serialize visibly. Preserve
  unrelated user work and do not auto-commit without authorization.
- **N04-W04:** Pause on blockers, consequential decisions or uncertain results;
  reconcile partial work before retry. Unsupported controls are not offered.

**Gate:** Actual app execution demonstrates a bounded work item, verification,
evidence, a failure or blocker and safe recovery for each advertised mode.

## N05: canvas integration

- **N05-W01:** Integrate idea, research, spec, plan, team, skills and execution
  into one coherent app canvas journey.
- **N05-W02:** Project durable authoritative artifacts without duplicating
  state; show phase status, dependencies, review, evidence, execution mode and
  actionable blockers. Reject stale actions and surface permissions and errors.
- **N05-W03:** Support keyboard navigation, focus and error announcements,
  accessible review, and safe rendering of untrusted content. Expose only
  controls proven by the host.

**Gate:** A real desktop journey covers both research paths, approval, team
preparation, start, evidence inspection, accessibility and an error state.

## N06: retirement and qualification

- **N06-W01:** Inventory consumers of standalone scripts, wrappers, packages,
  skills, tests, CI and documentation. Extract useful compatible code and
  replace dependencies before removing the launcher, engine and adapter.
- **N06-W02:** Preserve historical ADRs, changelogs and evidence. Update active
  README, architecture, requirements ownership, guides, skills, commands,
  documentation map and CI; distinguish retired commands from history.
- **N06-W03:** Provide explicit migration/export guidance and a rollback path
  for inherited artifacts. Never delete user projects or imply automatic
  migration without tested behavior.
- **N06-W04:** Run focused tests, typechecks, reference checks and real-app
  acceptance scenarios. Record versions, commands, results, limitations and
  operator review. Mocks do not prove host integration.

**Gate:** The supported app works without the retired standalone runtime and
the operator accepts release evidence.

## Risks and verification rules

Separate session creation may be disabled; experimental subagent APIs may lack
isolation or reliable recovery. Canvas permissions, provider behavior and
availability vary by host. Discovered skills are untrusted until reviewed.
Retirement can break references or destroy user work if done prematurely.
Test each advertised capability and fail visibly on uncertainty.

Each evidence record identifies work, environment, procedure, expected and
actual results, outcome, limitations and reviewer as applicable. Preserve
failed, blocked and superseded observations. Keep credentials, raw project
data and sensitive diagnostics out of public evidence.
